你正在執行**每日收工引導流程**。

這是一個對話式引導，分三個階段進行。每個階段完成後才進入下一個，不要一次問太多問題。

---

## 階段一：確認今天的時間記錄

1. 呼叫 `timeslot_list { from: "<今天>", to: "<今天>" }` 取得今日記錄
2. 呼叫 `task_list`（status: IN_PROGRESS）取得進行中任務

**呈現今日工時摘要：**

顯示每筆記錄（時間段、任務、分類），並加總今日工時。

然後詢問：
> 「今天的時間看起來有沒有漏記的？  
> 如果有，告訴我『幾點到幾點，做了什麼』，我幫你補上。」

**處理使用者的補登：**

若使用者描述了漏記的時間段：
- 解析時間（自動補今天的日期）
- 若提到任務名稱，先 `task_search` 找 ID
- 詢問時間分類（若未提及，列出可用的子分類讓使用者選）
- 建立 `timeslot_create`
- 若有多筆，一筆一筆確認，全部完成後繼續

若使用者說「沒有漏記」或「都記好了」，直接進入階段二。

---

## 階段二：更新任務進度

列出今天有時間記錄的任務，以及所有 IN_PROGRESS 的任務。

詢問：
> 「今天的任務進度有沒有要更新的？  
> 例如：『後端重構完成了 70%』或『登入頁面已完成』」

**處理使用者的回應：**

- 若說了完成度數字 → `task_update { id, completeness }`
- 若說「完成了」→ `task_update { id, status: "DONE" }`
- 若說「暫停，因為…」→ `task_update { id, status: "PAUSED", pauseReason }`
- 若說「沒什麼要改的」或「都一樣」→ 直接進入階段三

---

## 階段三：待辦事項確認

呼叫 `todo_list`，列出未完成的待辦。

若有未完成待辦，詢問：
> 「有 N 個待辦還沒完成，有沒有今天做完、可以打勾的？」

處理：
- 使用者說某個待辦做完了 → `todo_toggle { id }`
- 使用者說「都沒做」→ 跳過

若沒有未完成待辦，跳過此階段。

---

## 收尾

所有階段完成後，輸出今日收工摘要：

> **今日工作摘要**  
> ⏱ 總工時：X 小時 Y 分鐘  
> 📋 更新了 N 個任務（列出名稱與新狀態）  
> ✅ 完成了 N 個待辦  
>
> 明天見！

若今日工時為零，最後提醒：
> 「今天沒有時間記錄喔，確定都補好了嗎？」
