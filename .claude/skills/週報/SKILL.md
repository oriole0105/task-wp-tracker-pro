---

你正在執行**週報產生引導流程**。

分三個階段，每個階段完成後才進入下一個。

---

## 前置：確認目標週

計算「本週」的週一與週五日期（以今天為基準）。

詢問使用者：
> 「要產生本週（MM/DD–MM/DD）的週報嗎？還是其他週？」

- 若使用者確認本週或直接說「對」→ 使用本週的週一/週五
- 若使用者指定其他日期（例如「上週」、「5/9 那週」）→ 計算該週的週一/週五

以下步驟中：
- **weekStart** = 目標週的週一（YYYY-MM-DD）
- **weekEnd** = 目標週的週五（YYYY-MM-DD）
- **anchorDate** = weekEnd（週五，用於 `report_weekly`）

---

## 階段一：更新任務週快照

**目的：** 確保每個進行中的任務都有本週的完成度記錄，週報的進度趨勢才準確。

1. 呼叫 `task_list`，篩選 status 為 `IN_PROGRESS` 或 `PAUSED` 的任務
2. 對每個任務呼叫 `task_get { id }` 檢查是否已有 weekStart 的 weeklySnapshot

**分組列出：**

```
【已有本週快照】
• 1.1 後端重構 — 60%（說明：完成 DB schema）
• 1.2 API 文件 — 80%

【尚未更新本週快照】（需要填寫）
• 2.1 登入頁面設計
• 2.2 前端整合測試
```

若所有任務都已有快照，顯示清單後直接進入階段二，不需要詢問。

若有尚未更新的任務，詢問：
> 「尚未更新快照的任務，請依序填寫本週完成度與說明。  
> 格式：`任務名稱 完成度% 說明`（說明可省略）  
> 例如：`登入頁面 75% 完成 RWD 版面`」

**處理回應：**
- 解析使用者輸入的每個任務更新
- 呼叫 `task_update_snapshot { id, weekStart, completeness, note }`
- 若使用者說「跳過」或「不填」→ 跳過該任務
- 全部處理完後進入階段二

---

## 階段二：確認工時記錄

**目的：** 確保這週的時間記錄都補齊了，週報中的工時統計才正確。

1. 呼叫 `timeslot_list { from: weekStart, to: weekEnd }`
2. 依日期分組顯示工時摘要：

```
本週工時記錄（Mon–Fri）：
• 週一 05/12：2h 30m（後端重構 2h、開會 30m）
• 週二 05/13：3h 00m（後端重構 1.5h、文件撰寫 1.5h）
• 週三 05/14：0h（無記錄）⚠
• 週四 05/15：4h 00m（API 文件 3h、code review 1h）
• 週五 05/16：1h 30m（開會 1h、整理 30m）
────────────────
本週合計：11h 00m
```

工時為 0 的工作日標示 `⚠`。

然後詢問：
> 「有沒有漏記的時間？可以直接用簡寫補登，例如：  
> `週三 9-11:30 後端重構 程式開發`  
> 確認沒有漏記的話，直接說『沒有』就好。」

**處理補登：**
- 依 CLAUDE.md「時間簡寫格式」規則解析
- 週的相對日期（「週三」「週一」）換算為 weekStart 範圍內的實際日期
- 解析後列出確認清單，確認後批次建立 `timeslot_create`
- 補登完成後，重新計算並顯示更新後的合計

若使用者說「沒有」→ 直接進入階段三。

---

## 階段三：產生週報

所有資料確認完畢後，詢問：
> 「資料都準備好了，現在產生週報嗎？」

呼叫：
```
report_weekly { anchorDate: "<weekEnd>", format: "adoc" }
```

**輸出後：**

直接呈現週報的 AsciiDoc 全文，不需要額外包裝。

最後一行提示：
> 「週報已產生。可以直接複製上方內容貼入週報文件。」

---

## 注意事項

- 階段一若任務數量很多（>10），優先處理有時間記錄的任務，其餘可讓使用者選擇跳過
- 階段二若整週工時為零，特別提醒：「這週完全沒有時間記錄，確定嗎？」
- `task_update_snapshot` 的 weekStart 必須是**週一**（不是週五）
